Top 10 Technical Interview Questions & Answers

Q1: Why AWS Lambda over EC2?
Cost, scaling, and zero server maintenance. Lambda scales from 0 to thousands instantly, runs in milliseconds, and is 100% free within 1M requests/month.
Q2: Why containerized Lambdas over ZIP?
Eliminates the 250MB size limit (allows up to 10GB payloads), allows custom OS packages, and creates a unified packaging standard across ECS/EKS/Lambda.
Q3: Why Prometheus Pushgateway for Lambda?
Prometheus is pull-based. Lambda runs for only 500ms and dies. Pushgateway acts as an intermediary cache where Lambda pushes metrics before terminating.
Q4: Why Terraform Remote S3 Backend in CI/CD?
GitHub Actions runs on fresh Ubuntu VMs with no local state file. Storing state in S3 gives local engineers and CI runners a single shared source of truth.
Q5: How did you secure credentials in GitHub Actions?
Used GitHub Encrypted Secrets (AES-256), excluded sensitive files via .gitignore, and enabled GitHub Secret Scanning Push Protection.
Q6: How does the ETL data flow work?
S3 upload triggers Extractor (schema validation) $\rightarrow$ async invokes Transformer (keyword heuristic categorization & priority) $\rightarrow$ async invokes Loader (DynamoDB write + S3 date-partitioned archive).
Q7: Why DynamoDB over RDS/Postgres?
Tickets are semi-structured JSON documents. DynamoDB is serverless, fast, zero-maintenance, and offers 25 GB permanent free storage with PAY_PER_REQUEST.
Q8: What Docker Lambda manifest error occurred and how was it solved?
Lambda rejected multi-arch index attestations. Fixed by adding --platform linux/amd64 --provenance=false to generate clean Docker v2 images.
Q9: What does CI validate before deploy?
Flake8 code linting, Pytest unit tests on transformer logic, and Terraform format check & validation.
Q10: How do you guarantee $0.00 spend?
Architected within free tier limits (Lambda, S3, DynamoDB, ECR), local Docker Compose observability, and an automated teardown.ps1 script.
